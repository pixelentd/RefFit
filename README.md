# RefFit

A phone app for training the football/soccer referee interval fitness test (40 × 75m run /
25m walk) — a configurable interval trainer with GPS distance targets, audio cues, and an
on-screen timer.

Stack: Capacitor + React + Vite + TypeScript (strict). Developed on Windows; the web target
(this PWA) needs no Mac and no Xcode. A native iOS build via Capacitor is a possible later
step, but is not part of this app today.

## Development

```
npm install
npm run dev       # http://localhost:5173, hot-reloading
npm test          # Vitest — the engine + audio decision logic
npm run build     # tsc -b && vite build -> dist/
npm run preview   # serves the built dist/ locally, close to production
```

`tsc`'s own build output is redirected into `node_modules/.tsc-out` (see `tsconfig*.json`) so
nothing leaks into the repo root — the only build output that matters is `dist/`.

## PWA

The app is a installable, offline-capable Progressive Web App (`vite-plugin-pwa`, Workbox
`generateSW` precache strategy): after the first load, the whole app shell is cached and the
app opens and runs with **no network at all** — the point, since it's meant to run on a track
with no signal.

- **Base path** — `vite.config.ts` has a single `BASE_PATH` constant (default `'/'`, i.e. a
  domain/subdomain root). The manifest's `start_url`/`scope`, the service worker's registration
  path, and every asset URL Vite emits all derive from it. If you ever deploy into a subfolder
  instead (`https://yoursite.com/reffit/`), change `BASE_PATH` to `'/reffit/'` and rebuild —
  nothing else needs to change.
- **Icons** are placeholders: a blocky "R" monogram generated by `node scripts/generate-icons.mjs`
  (pure Node + built-in `zlib`, no image library) into `public/icons/`. Re-run that script any
  time you want to regenerate them (e.g. after picking different colors), or just replace the
  PNGs in `public/icons/` with real artwork of the same sizes (192, 512, 512 maskable, 180
  apple-touch-icon) — nothing else needs to know.
- **Screen Wake Lock** (`src/hooks/useScreenWakeLock.ts`) keeps the screen on for the length of
  a workout. This is load-bearing, not cosmetic: on iOS, Web Audio's beeps stop firing once the
  screen locks, so without this the audio cues would silently stop mid-run. If a browser doesn't
  support the Wake Lock API, the Run screen shows a "keep your screen on manually" hint instead.

### What the web route can't do

Running as a PWA instead of a native app means one real feature is off the table: **there's no
way to duck Amazon Music** (or anything else playing) when a cue beeps — that needs a native
`AVAudioSession` with `.duckOthers`, which only exists in a real iOS app. For the fitness test,
either run with music off, or play music from a separate speaker/device so it doesn't compete
with the phone's beeps.

## Deploying to Hostinger (free, via GitHub Actions)

Every push to `main` builds the app and uploads `dist/` to your Hostinger web root over FTP
(`.github/workflows/deploy.yml`). No paid GitHub or Hostinger features are involved.

### 1. Get FTP credentials from Hostinger

In **hPanel → Files → FTP Accounts**, either note the credentials for the account created with
your hosting plan, or create a new FTP account there. You'll need the **FTP host**, **username**,
and **password**.

### 2. Add them as GitHub Actions secrets

In your GitHub repo: **Settings → Secrets and variables → Actions → Secrets tab → New repository
secret**, and add three:

| Secret name     | Value                          |
|-----------------|---------------------------------|
| `FTP_HOST`      | The FTP host from hPanel        |
| `FTP_USERNAME`  | The FTP username from hPanel    |
| `FTP_PASSWORD`  | The FTP account's password      |

### 3. Set your web root (server-dir)

Still in **Settings → Secrets and variables → Actions**, switch to the **Variables** tab (not
Secrets — this one isn't sensitive) and add a repository variable named `FTP_SERVER_DIR`:

- Deploying to your **primary domain**: `./public_html/`  (this is also the workflow's fallback
  if you skip this step, so it works out of the box for that common case)
- Deploying to an **addon domain or subdomain** with its own document root: check
  **hPanel → Domains →** that domain's **Manage** page for its exact folder, typically something
  like `./public_html/your-subdomain/`

Either way, keep the trailing slash.

By default the deploy **uploads and overwrites, but never deletes** files already on the
server — safe if that web root has other things on it. If you want a true mirror (delete
anything on the server that isn't in this build), uncomment `dangerous-clean-slate: true` in
the workflow — only do that if the target folder is dedicated to this app.

### 4. Enable HTTPS

The app needs HTTPS: it's required for the service worker (so the PWA/offline behavior works
at all) and will be required for GPS next. In **hPanel → SSL**, issue the free SSL certificate
for your domain, and enable **Force HTTPS** so plain-`http://` requests redirect automatically.

### 5. Push

```
git push origin main
```

Watch the run under your repo's **Actions** tab. Once it's green, the site is live.

## Testing on your iPhone

1. Open the deployed **https://** URL in **Safari** (must be Safari, not Chrome/Firefox, for
   Add to Home Screen to install a real standalone app on iOS).
2. Tap **Share → Add to Home Screen**, then open RefFit from the home screen icon you just
   added (not the Safari tab) — that's what gets you the full-screen `standalone` app, no
   browser chrome.
3. Pick a workout and tap **Start**. Confirm you hear the beeps (countdown ticks, the
   run/walk/sprint/rest pitch on each phase-start, the warning cues, the finish flourish), and
   that the screen doesn't dim or lock while it's running.
4. Turn on **Airplane Mode**, then relaunch RefFit from the home screen. It should load and run
   exactly the same with zero network — that's the offline precache working.
